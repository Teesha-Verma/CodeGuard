# Retrieval Summary
OWASP ASVS V4.1.1 requires access control enforcement (deny by default). This verification rule ensures applications enforce deny all unauthorized request access attempts unless explicitly permitted by authorization rules. to prevent failure to enforce access control permits unauthenticated or low-privileged users to invoke restricted functionality. across Python web frameworks including FastAPI, Flask, and Django.

# Overview
Verify that access control is enforced on every request and denies access by default.

# Official Requirement
Verify that the application complies with OWASP ASVS V4.1.1 (V4 Access Control): Verify that access control is enforced on every request and denies access by default.

# Security Objective
Deny all unauthorized request access attempts unless explicitly permitted by authorization rules.

# Why This Matters
Failure to enforce access control permits unauthenticated or low-privileged users to invoke restricted functionality.

# Threat Model
Attacker accesses `/api/admin/users` directly because route lacks authorization decorator.

# Detection Guidance
AI code reviewers should scan Python source files for unvalidated usage of Depends(get_current_user), login_required, permission_required. Look for missing authorization, improper type checking, or un-parameterized dynamic input.

# AST Detection Hints
Target AST nodes: `ast.FunctionDef, ast.ClassDef, ast.Decorator`. Scan function definitions and calls matching these nodes.

# Regex / Search Hints
Use regex pattern: `(?i)@(app|router)\.(get|post|put|delete)\([^)]*\)(?!\s*@(?:login_required|permission))` to flag candidate vulnerabilities.

# Semantic Detection Hints
Exposing endpoint routes without explicit authentication or authorization middleware dependencies.

# Relevant Python APIs
`Depends(get_current_user), login_required, permission_required`

# Relevant Imports
`from fastapi import Depends, from flask_login import login_required`

# Vulnerable Patterns
Insecure implementation exposing security flaws:
```python
@app.get('/admin/data')
def get_admin_data(): return db.query_all()
```

# Secure Patterns
Secure implementation fulfilling ASVS V4.1.1:
```python
@app.get('/admin/data')
def get_admin_data(user=Depends(require_admin_user)): return db.query_all()
```

# Python Example
```python
@app.get('/admin/data')
def get_admin_data(user=Depends(require_admin_user)): return db.query_all()
```

# FastAPI Example
```python
def require_admin(user=Depends(get_current_user)):
    if not user.is_admin: raise HTTPException(403)
    return user
```

# Flask Example
```python
@app.route('/admin/data')
@login_required
def get_admin_data():
    if not current_user.is_admin: abort(403)
    return jsonify(db.get_admin_data())
```

# Django Example
```python
@user_passes_test(lambda u: u.is_superuser)
def admin_view(request): return render(request, 'admin.html')
```

# Common Developer Mistakes
Checking permissions in the frontend UI while leaving backend API endpoints exposed.

# False Positives
Explicitly public endpoints such as `/health`, `/login`, or `/docs`.

# False Negatives
Checking authentication but omitting role/permission authorization checks on sensitive actions.

# AI Review Heuristics
Flag any state-changing API route lacking authorization dependencies.

# Detection Confidence
Confidence level: **HIGH**

# Reasoning Chain
Verify presence of authentication and authorization decorators on route definitions.

# Review Checklist
- [ ] Verify requirement ASVS V4.1.1 is enforced in code.
- [ ] Confirm automated unit tests validate this constraint.
- [ ] Ensure secure default fallback if validation fails.

# Remediation
Apply centralized authorization middleware or require user context dependency on all routes.
