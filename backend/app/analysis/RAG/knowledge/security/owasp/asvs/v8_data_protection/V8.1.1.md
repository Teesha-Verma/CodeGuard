# Retrieval Summary
OWASP ASVS V8.1.1 requires sensitive data in-memory & storage protection. This verification rule ensures applications enforce ensure all persistent database fields containing pii, financial details, or secrets are encrypted at rest. to prevent unencrypted database backups or compromised storage volumes expose sensitive records to unauthorized disclosure. across Python web frameworks including FastAPI, Flask, and Django.

# Overview
Verify that sensitive data at rest is protected with strong encryption and appropriate access controls.

# Official Requirement
Verify that the application complies with OWASP ASVS V8.1.1 (V8 Data Protection): Verify that sensitive data at rest is protected with strong encryption and appropriate access controls.

# Security Objective
Ensure all persistent database fields containing PII, financial details, or secrets are encrypted at rest.

# Why This Matters
Unencrypted database backups or compromised storage volumes expose sensitive records to unauthorized disclosure.

# Threat Model
Attacker steals unencrypted database backup file from S3 bucket and extracts user social security numbers.

# Detection Guidance
AI code reviewers should scan Python source files for unvalidated usage of cryptography.fernet.Fernet, sqlalchemy_utils.EncryptedType. Look for missing authorization, improper type checking, or un-parameterized dynamic input.

# AST Detection Hints
Target AST nodes: `ast.ClassDef (SQLAlchemy models), ast.Call (Fernet, AESGCM)`. Scan function definitions and calls matching these nodes.

# Regex / Search Hints
Use regex pattern: `(?i)(ssn|credit_card|secret_key)\s*=\s*Column\(String` to flag candidate vulnerabilities.

# Semantic Detection Hints
Storing PII fields in plain text database columns without encryption layers.

# Relevant Python APIs
`cryptography.fernet.Fernet, sqlalchemy_utils.EncryptedType`

# Relevant Imports
`from cryptography.fernet import Fernet, from sqlalchemy_utils import EncryptedType`

# Vulnerable Patterns
Insecure implementation exposing security flaws:
```python
class User(Base):
    ssn = Column(String) # VULNERABLE
```

# Secure Patterns
Secure implementation fulfilling ASVS V8.1.1:
```python
class User(Base):
    ssn = Column(EncryptedType(String, secret_key, FernetEngine)) # SECURE
```

# Python Example
```python
class User(Base):
    ssn = Column(EncryptedType(String, secret_key, FernetEngine)) # SECURE
```

# FastAPI Example
```python
user.ssn = fernet.encrypt(raw_ssn.encode()).decode()
```

# Flask Example
```python
raw_ssn = fernet.decrypt(user.encrypted_ssn.encode()).decode()
```

# Django Example
```python
class Profile(models.Model):
    ssn = EncryptedCharField(max_length=100)
```

# SQLAlchemy Considerations
ssn = Column(EncryptedType(String, secret_key, FernetEngine))

# PostgreSQL Considerations
```sql
INSERT INTO users (ssn) VALUES (pgp_sym_encrypt('123-45-6789', 'AES_KEY'));
```

# Common Developer Mistakes
Encrypting data with keys stored directly alongside the database in the same container.

# False Positives
Hashing non-reversible tokens (like password hashes) which do not require encryption at rest.

# False Negatives
Encrypting primary database tables but failing to encrypt database dump files or redis caches.

# AI Review Heuristics
Flag database model fields holding sensitive labels defined as raw String without encryption wrapper.

# Detection Confidence
Confidence level: **HIGH**

# Reasoning Chain
Inspect database model definitions and check for missing cipher wrappers on PII fields.

# Review Checklist
- [ ] Verify requirement ASVS V8.1.1 is enforced in code.
- [ ] Confirm automated unit tests validate this constraint.
- [ ] Ensure secure default fallback if validation fails.

# Remediation
Apply column-level encryption or transparent data encryption (TDE) for sensitive database fields.
