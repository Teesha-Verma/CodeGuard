# Retrieval Summary
OWASP ASVS V3.2.1 requires session binding & cookie security flags. This verification rule ensures applications enforce ensure session identifiers are cryptographically bound and protected from client-side script theft and cross-site requests. to prevent missing httponly allows attackers executing xss to read document.cookie and hijack sessions. across Python web frameworks including FastAPI, Flask, and Django.

# Overview
Verify that session cookies have HttpOnly, Secure, and SameSite flags set to prevent XSS theft and CSRF.

# Official Requirement
Verify that the application complies with OWASP ASVS V3.2.1 (V3 Session Management): Verify that session cookies have HttpOnly, Secure, and SameSite flags set to prevent XSS theft and CSRF.

# Security Objective
Ensure session identifiers are cryptographically bound and protected from client-side script theft and cross-site requests.

# Why This Matters
Missing HttpOnly allows attackers executing XSS to read document.cookie and hijack sessions.

# Threat Model
Attacker intercepts unencrypted session cookie over public Wi-Fi or steals session token via XSS.

# Detection Guidance
AI code reviewers should scan Python source files for unvalidated usage of Response.set_cookie, set_cookie. Look for missing authorization, improper type checking, or un-parameterized dynamic input.

# AST Detection Hints
Target AST nodes: `ast.Call (set_cookie, set_cookie_header)`. Scan function definitions and calls matching these nodes.

# Regex / Search Hints
Use regex pattern: `(?i)set_cookie\((?:(?!httponly=True).)*\)` to flag candidate vulnerabilities.

# Semantic Detection Hints
Cookie issuance without HttpOnly=True, Secure=True, and SameSite=Lax/Strict.

# Relevant Python APIs
`Response.set_cookie, set_cookie`

# Relevant Imports
`from fastapi import Response, from flask import make_response`

# Vulnerable Patterns
Insecure implementation exposing security flaws:
```python
response.set_cookie('session_id', token)
```

# Secure Patterns
Secure implementation fulfilling ASVS V3.2.1:
```python
response.set_cookie('session_id', token, httponly=True, secure=True, samesite='Strict')
```

# Python Example
```python
response.set_cookie('session_id', token, httponly=True, secure=True, samesite='Strict')
```

# FastAPI Example
```python
response.set_cookie(key='session_id', value=token, httponly=True, secure=True, samesite='lax')
```

# Flask Example
```python
resp = make_response(render_template('index.html'))
resp.set_cookie('session_id', token, httponly=True, secure=True, samesite='Lax')
```

# Django Example
```python
SESSION_COOKIE_HTTPONLY = True
SESSION_COOKIE_SECURE = True
SESSION_COOKIE_SAMESITE = 'Lax'
```

# Common Developer Mistakes
Setting `samesite='None'` without enforcing `secure=True`.

# False Positives
Setting cookies for non-sensitive public preferences without HttpOnly.

# False Negatives
Setting correct flags on custom cookies but omitting them on framework session defaults.

# AI Review Heuristics
Flag all `set_cookie` calls where `httponly` or `secure` is False or absent.

# Detection Confidence
Confidence level: **HIGH**

# Reasoning Chain
Scan set_cookie invocations and check for missing HttpOnly, Secure, SameSite parameters.

# Review Checklist
- [ ] Verify requirement ASVS V3.2.1 is enforced in code.
- [ ] Confirm automated unit tests validate this constraint.
- [ ] Ensure secure default fallback if validation fails.

# Remediation
Add `httponly=True`, `secure=True`, and `samesite='Lax'` to all session cookie assignments.
