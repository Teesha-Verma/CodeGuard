# Retrieval Summary
OWASP ASVS V5.3.1 requires parameterized sql database queries. This verification rule ensures applications enforce ensure database queries separate sql command structure from user parameters. to prevent dynamic string concatenation allows attackers to manipulate query logic and exfiltrate databases. across Python web frameworks including FastAPI, Flask, and Django.

# Overview
Verify that all database queries use parameterized SQL prepared statements to prevent SQL Injection.

# Official Requirement
Verify that the application complies with OWASP ASVS V5.3.1 (V5 Validation, Sanitization & Encoding): Verify that all database queries use parameterized SQL prepared statements to prevent SQL Injection.

# Security Objective
Ensure database queries separate SQL command structure from user parameters.

# Why This Matters
Dynamic string concatenation allows attackers to manipulate query logic and exfiltrate databases.

# Threat Model
Attacker inputs `' OR '1'='1` into login form to bypass authentication and dump entire table.

# Detection Guidance
AI code reviewers should scan Python source files for unvalidated usage of cursor.execute, session.execute, text(). Look for missing authorization, improper type checking, or un-parameterized dynamic input.

# AST Detection Hints
Target AST nodes: `ast.Call (execute, raw, query), ast.JoinedStr (f-strings)`. Scan function definitions and calls matching these nodes.

# Regex / Search Hints
Use regex pattern: `(?i)(execute|raw)\(\s*f['\"].*SELECT|INSERT|UPDATE|DELETE` to flag candidate vulnerabilities.

# Semantic Detection Hints
Constructing SQL strings using format strings or `%` operators before passing to database execution sinks.

# Relevant Python APIs
`cursor.execute, session.execute, text()`

# Relevant Imports
`from sqlalchemy import text, import psycopg2`

# Vulnerable Patterns
Insecure implementation exposing security flaws:
```python
cursor.execute(f'SELECT * FROM users WHERE email = "{user_input}"')
```

# Secure Patterns
Secure implementation fulfilling ASVS V5.3.1:
```python
cursor.execute('SELECT * FROM users WHERE email = %s', (user_input,))
```

# Python Example
```python
cursor.execute('SELECT * FROM users WHERE email = %s', (user_input,))
```

# FastAPI Example
```python
@app.get('/users')
def get_user(email: str, db: Session = Depends(get_db)):
    return db.execute(text('SELECT * FROM users WHERE email = :e'), {'e': email}).fetchall()
```

# Flask Example
```python
@app.route('/user')
def user():
    e = request.args.get('email')
    return jsonify(db.session.execute(text('SELECT * FROM users WHERE email = :e'), {'e': e}).fetchall())
```

# Django Example
```python
User.objects.filter(email=user_input)
```

# SQLAlchemy Considerations
session.query(User).filter(User.email == user_input)

# PostgreSQL Considerations
```sql
PREPARE get_user (text) AS SELECT * FROM users WHERE email = $1;
EXECUTE get_user('admin@example.com');
```

# Common Developer Mistakes
Using ORMs but calling raw SQL helper methods with f-strings.

# False Positives
Concatenating hardcoded static strings derived strictly from internal enum allowlists.

# False Negatives
Passing pre-formatted strings into ORM `.extra()` or `raw()` queries.

# AI Review Heuristics
Flag any `execute()` call where the query string is constructed via f-string or `%` formatting.

# Detection Confidence
Confidence level: **HIGH**

# Reasoning Chain
Inspect database execution sinks and flag dynamic SQL string construction.

# Review Checklist
- [ ] Verify requirement ASVS V5.3.1 is enforced in code.
- [ ] Confirm automated unit tests validate this constraint.
- [ ] Ensure secure default fallback if validation fails.

# Remediation
Replace all raw string formatted SQL statements with parameterized prepared statements.
