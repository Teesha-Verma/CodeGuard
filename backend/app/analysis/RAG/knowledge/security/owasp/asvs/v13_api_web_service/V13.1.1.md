# Retrieval Summary
OWASP ASVS V13.1.1 requires api token signature & payload validation. This verification rule ensures applications enforce ensure api bearer tokens validate signature integrity and payload claims. to prevent unverified jwt tokens allow attackers to tamper with claim values and bypass authorization. across Python web frameworks including FastAPI, Flask, and Django.

# Overview
Verify that API authentication tokens (JWT) enforce cryptographic signature verification and payload schema validation.

# Official Requirement
Verify that the application complies with OWASP ASVS V13.1.1 (V13 API & Web Service): Verify that API authentication tokens (JWT) enforce cryptographic signature verification and payload schema validation.

# Security Objective
Ensure API bearer tokens validate signature integrity and payload claims.

# Why This Matters
Unverified JWT tokens allow attackers to tamper with claim values and bypass authorization.

# Threat Model
Attacker modifies JWT payload claim `"role": "user"` to `"role": "admin"` and sends request with `"alg": "none"`.

# Detection Guidance
AI code reviewers should scan Python source files for unvalidated usage of jwt.decode, jose.jwt.decode. Look for missing authorization, improper type checking, or un-parameterized dynamic input.

# AST Detection Hints
Target AST nodes: `ast.Call (jwt.decode, jwt.PyJWT)`. Scan function definitions and calls matching these nodes.

# Regex / Search Hints
Use regex pattern: `(?i)jwt\.decode\([^)]*verify_signature\s*=\s*False` to flag candidate vulnerabilities.

# Semantic Detection Hints
Decoding JWT tokens without specifying allowed signature algorithms or setting verify_signature=False.

# Relevant Python APIs
`jwt.decode, jose.jwt.decode`

# Relevant Imports
`import jwt, from jose import jwt`

# Vulnerable Patterns
Insecure implementation exposing security flaws:
```python
def parse(t): return jwt.decode(t, options={'verify_signature': False})
```

# Secure Patterns
Secure implementation fulfilling ASVS V13.1.1:
```python
def parse(t): return jwt.decode(t, SECRET_KEY, algorithms=['HS256'])
```

# Python Example
```python
def parse(t): return jwt.decode(t, SECRET_KEY, algorithms=['HS256'])
```

# FastAPI Example
```python
def get_user(t: str = Depends(oauth2_scheme)):
    try: return jwt.decode(t, SECRET_KEY, algorithms=['HS256'])
    except JWTError: raise HTTPException(401)
```

# Flask Example
```python
@app.before_request
def verify_jwt():
    auth_header = request.headers.get('Authorization')
    if auth_header: g.user = jwt.decode(auth_header.split(' ')[1], SECRET_KEY, algorithms=['HS256'])
```

# Common Developer Mistakes
Accepting `none` algorithm in JWT decode parameters.

# False Positives
Parsing public token headers strictly for un-authenticated analytics tracking prior to auth layer.

# False Negatives
Verifying signature but failing to check token expiration `exp` claim.

# AI Review Heuristics
Flag any `jwt.decode` call where algorithms list is missing or signature verification is disabled.

# Detection Confidence
Confidence level: **HIGH**

# Reasoning Chain
Inspect jwt.decode parameters and flag missing algorithms list or disabled signature verification.

# Review Checklist
- [ ] Verify requirement ASVS V13.1.1 is enforced in code.
- [ ] Confirm automated unit tests validate this constraint.
- [ ] Ensure secure default fallback if validation fails.

# Remediation
Enforce signature verification and pass explicit allowed algorithms list to `jwt.decode()`.
