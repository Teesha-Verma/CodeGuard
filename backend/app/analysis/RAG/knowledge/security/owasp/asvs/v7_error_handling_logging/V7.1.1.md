# Retrieval Summary
OWASP ASVS V7.1.1 requires log content security & pii protection. This verification rule ensures applications enforce prevent sensitive user credentials and tokens from leaking into log storage or monitoring tools. to prevent logs accessible to operations staff can leak plain passwords and session keys if not redacted. across Python web frameworks including FastAPI, Flask, and Django.

# Overview
Verify that sensitive data such as passwords, tokens, PII, and credit card numbers are never logged in cleartext.

# Official Requirement
Verify that the application complies with OWASP ASVS V7.1.1 (V7 Error Handling & Logging): Verify that sensitive data such as passwords, tokens, PII, and credit card numbers are never logged in cleartext.

# Security Objective
Prevent sensitive user credentials and tokens from leaking into log storage or monitoring tools.

# Why This Matters
Logs accessible to operations staff can leak plain passwords and session keys if not redacted.

# Threat Model
Attacker compromises SIEM platform and reads plain text user passwords emitted during login exceptions.

# Detection Guidance
AI code reviewers should scan Python source files for unvalidated usage of logging.getLogger, structlog.get_logger. Look for missing authorization, improper type checking, or un-parameterized dynamic input.

# AST Detection Hints
Target AST nodes: `ast.Call (logging.info, logger.debug, print)`. Scan function definitions and calls matching these nodes.

# Regex / Search Hints
Use regex pattern: `(?i)log(ger)?\.(info|debug|error)\(.*(password|secret|token|ssn|credit_card)` to flag candidate vulnerabilities.

# Semantic Detection Hints
Logging raw request headers or request bodies containing authentication credentials.

# Relevant Python APIs
`logging.getLogger, structlog.get_logger`

# Relevant Imports
`import logging, import structlog`

# Vulnerable Patterns
Insecure implementation exposing security flaws:
```python
logger.info(f'User login attempt: {username} with password: {password}')
```

# Secure Patterns
Secure implementation fulfilling ASVS V7.1.1:
```python
logger.info('User login attempt', extra={'username': username, 'status': 'initiated'})
```

# Python Example
```python
logger.info('User login attempt', extra={'username': username, 'status': 'initiated'})
```

# FastAPI Example
```python
@app.post('/login')
def login(credentials: LoginSchema):
    logger.info('Login attempt for user=%s', credentials.username)
```

# Flask Example
```python
@app.route('/login', methods=['POST'])
def login():
    logger.info('Login endpoint called by ip=%s', request.remote_addr)
```

# Django Example
```python
@sensitive_post_parameters('password')
def login_view(request): pass
```

# Common Developer Mistakes
Printing raw exception objects `logger.error(ex)` containing full request strings with passwords.

# False Positives
Logging masked or hashed identifier tokens.

# False Negatives
Filtering form parameters but failing to redact sensitive JSON body attributes.

# AI Review Heuristics
Flag any log call formatting variables named `password`, `secret`, or `token`.

# Detection Confidence
Confidence level: **HIGH**

# Reasoning Chain
Inspect log statement format strings and flag sensitive credential logging.

# Review Checklist
- [ ] Verify requirement ASVS V7.1.1 is enforced in code.
- [ ] Confirm automated unit tests validate this constraint.
- [ ] Ensure secure default fallback if validation fails.

# Remediation
Redact or mask sensitive credentials from log payloads prior to output stream.
