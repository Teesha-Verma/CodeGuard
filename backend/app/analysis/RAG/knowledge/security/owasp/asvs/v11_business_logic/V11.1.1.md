# Retrieval Summary
OWASP ASVS V11.1.1 requires business logic integrity & workflow enforcement. This verification rule ensures applications enforce ensure multi-step business flows cannot be skipped or manipulated to bypass validation steps. to prevent attackers can bypass step 2 (payment confirmation) and jump directly to step 3 (order delivery) if state is not verified server-side. across Python web frameworks including FastAPI, Flask, and Django.

# Overview
Verify that application business workflows enforce step ordering and state validation to prevent workflow circumvention.

# Official Requirement
Verify that the application complies with OWASP ASVS V11.1.1 (V11 Business Logic): Verify that application business workflows enforce step ordering and state validation to prevent workflow circumvention.

# Security Objective
Ensure multi-step business flows cannot be skipped or manipulated to bypass validation steps.

# Why This Matters
Attackers can bypass step 2 (payment confirmation) and jump directly to step 3 (order delivery) if state is not verified server-side.

# Threat Model
Attacker submits HTTP request directly to `/checkout/success` with arbitrary order ID without paying.

# Detection Guidance
AI code reviewers should scan Python source files for unvalidated usage of db.session.query, state_machine.validate. Look for missing authorization, improper type checking, or un-parameterized dynamic input.

# AST Detection Hints
Target AST nodes: `ast.FunctionDef, ast.If (state checks)`. Scan function definitions and calls matching these nodes.

# Regex / Search Hints
Use regex pattern: `(?i)def (checkout_complete|order_fulfill)` to flag candidate vulnerabilities.

# Semantic Detection Hints
Executing high-privilege business actions without checking current transaction state in backend database.

# Relevant Python APIs
`db.session.query, state_machine.validate`

# Relevant Imports
`from enum import Enum`

# Vulnerable Patterns
Insecure implementation exposing security flaws:
```python
@app.post('/order/complete')
def complete(order_id: int): db.mark_fulfilled(order_id)
```

# Secure Patterns
Secure implementation fulfilling ASVS V11.1.1:
```python
@app.post('/order/complete')
def complete(order_id: int):
    order = db.get_order(order_id)
    if order.status != OrderStatus.PAID: raise HTTPException(400, 'Not paid')
    order.status = OrderStatus.FULFILLED; db.commit()
```

# FastAPI Example
```python
@app.post('/checkout/fulfill')
def fulfill(order_id: int, db: Session = Depends(get_db)):
    order = db.query(Order).filter(Order.id == order_id).first()
    if not order or order.status != 'PAID': raise HTTPException(400)
    order.status = 'FULFILLED'; db.commit()
```

# Flask Example
```python
@app.route('/checkout/fulfill', methods=['POST'])
def fulfill():
    order = Order.query.get_or_404(request.json['order_id'])
    if order.status != 'PAID': abort(400)
    order.status = 'FULFILLED'; db.session.commit()
```

# Django Example
```python
def fulfill(request, order_id):
    order = get_object_or_404(Order, id=order_id)
    if order.status != OrderStatus.PAID: return HttpResponseBadRequest()
    order.status = OrderStatus.FULFILLED; order.save()
```

# Common Developer Mistakes
Relying on client session variables to track multi-step form progress instead of database state.

# False Positives
Idempotent administrative status override endpoints reserved for customer support roles.

# False Negatives
Checking state flags but failing to lock the database row, opening window for race conditions.

# AI Review Heuristics
Flag state-updating methods that omit explicit status verification prior to mutation.
