# Retrieval Summary
OWASP ASVS V10.1.1 requires safe serialization & deserialization prevention. This verification rule ensures applications enforce prevent remote code execution (rce) by avoiding execution of arbitrary code during object reconstruction. to prevent insecure deserialization of arbitrary payloads allows attackers to instantiate dangerous objects and execute arbitrary shell commands. across Python web frameworks including FastAPI, Flask, and Django.

# Overview
Verify that untrusted data is never deserialized using insecure object serializers like pickle, marshal, or PyYAML unsafe loads.

# Official Requirement
Verify that the application complies with OWASP ASVS V10.1.1 (V10 Malicious Code): Verify that untrusted data is never deserialized using insecure object serializers like pickle, marshal, or PyYAML unsafe loads.

# Security Objective
Prevent Remote Code Execution (RCE) by avoiding execution of arbitrary code during object reconstruction.

# Why This Matters
Insecure deserialization of arbitrary payloads allows attackers to instantiate dangerous objects and execute arbitrary shell commands.

# Threat Model
Attacker crafts malicious `__reduce__` pickle payload sent in cookie to achieve full server shell execution.

# Detection Guidance
AI code reviewers should scan Python source files for unvalidated usage of json.loads, pydantic.BaseModel.parse_raw, yaml.safe_load. Look for missing authorization, improper type checking, or un-parameterized dynamic input.

# AST Detection Hints
Target AST nodes: `ast.Call (pickle.loads, marshal.loads, yaml.load)`. Scan function definitions and calls matching these nodes.

# Regex / Search Hints
Use regex pattern: `(?i)(pickle\.loads|marshal\.loads|yaml\.load\([^,)]*\))` to flag candidate vulnerabilities.

# Semantic Detection Hints
Deserializing binary stream or user-supplied string data into Python objects using unsafe methods.

# Relevant Python APIs
`json.loads, pydantic.BaseModel.parse_raw, yaml.safe_load`

# Relevant Imports
`import json, import pydantic, import yaml`

# Vulnerable Patterns
Insecure implementation exposing security flaws:
```python
import pickle
@app.post('/session')
def restore(data: bytes): return pickle.loads(data)
```

# Secure Patterns
Secure implementation fulfilling ASVS V10.1.1:
```python
import json
@app.post('/session')
def restore(data: str): return json.loads(data)
```

# Python Example
```python
import json
```

# Common Developer Mistakes
Using `yaml.load(data)` without specifying `Loader=yaml.SafeLoader`.

# False Positives
Deserializing trusted internal static configuration files packaged strictly within deployment artifact.

# False Negatives
Replacing `pickle` with `shelve` or `dill` which remain vulnerable to insecure object instantiation.

# AI Review Heuristics
Flag all occurrences of `pickle.loads()`, `marshal.loads()`, or `yaml.load()` without SafeLoader.

# Detection Confidence
Confidence level: **HIGH**

# Reasoning Chain
Locate object deserialization method calls and flag use of pickle or unsafe PyYAML.

# Review Checklist
- [ ] Verify requirement ASVS V10.1.1 is enforced in code.
- [ ] Confirm automated unit tests validate this constraint.
- [ ] Ensure secure default fallback if validation fails.

# Remediation
Replace pickle and unsafe serializers with JSON, Protocol Buffers, or Pydantic schemas.
